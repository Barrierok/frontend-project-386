# Доменные документы

Как инженерные скиллы должны использовать доменную документацию этого репозитория при исследовании кода.

## Перед исследованием прочитайте

- **`GLOSSARY.md`** в корне репозитория, либо
- **`GLOSSARY-MAP.md`** в корне, если он есть: он указывает на по одному `GLOSSARY.md` на контекст. Прочитайте каждый, релевантный теме.
- **`docs/adr/`**: прочитайте ADR, затрагивающие область, в которой собираетесь работать. В мультиконтекстных репозиториях дополнительно проверяйте `src/<context>/docs/adr/` на решения уровня контекста.

Если каких-то из этих файлов нет, **проходите молча**. Не отмечайте их отсутствие и не предлагайте создать их заранее. Скилл `/domain-modeling` (доступный через `/grill-with-docs` и `/improve-codebase-architecture`) создаёт их лениво, когда термины или решения действительно зафиксированы.

## Структура файлов

Single-context репозиторий (большинство репозиториев, включая этот):

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Мультиконтекстный репозиторий (признак — `GLOSSARY-MAP.md` в корне):

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← общесистемные решения
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← решения контекста
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

## Используйте словарь глоссария

Когда в вашем результате называется доменное понятие (в заголовке issue, предложении рефакторинга, гипотезе, имени теста), используйте термин в том значении, которое задано в `GLOSSARY.md`. Не уходите в синонимы, которые глоссарий явно избегает.

Если нужного понятия в глоссарии ещё нет, это сигнал: либо вы придумываете язык, которого в проекте нет (пересмотрите), либо есть реальный пробел (отметьте его для `/domain-modeling`).

## Отмечайте конфликты с ADR

Если ваш результат противоречит существующему ADR, явно об этом скажите, а не переопределяйте молча:

> _Противоречит ADR-0007 (event-sourced orders), но стоит переоткрыть, потому что…_
